# [作成計画] 要件定義書および仕様書の作成

本プロジェクト「ショキミツ」のこれまでの開発内容に基づき、正式な要件定義書と仕様書を作成します。
これらは、今後の機能拡張や上司・関係者への説明のための正式な公式ドキュメントとなります。

## 構成案

### 1. 要件定義書 (Requirements Definition)
プロジェクトの目的、ターゲットユーザー、解決すべき課題、および提供する機能をビジネス視点で定義します。

**主な記載項目:**
- **システム概要**: 保守契約管理・見積作成のDX化の目的
- **現状の課題**: 手動計算のミス、複数のExcelテンプレート管理の煩雑さ、顧客データの散逸
- **解決策**: Webアプリケーションによる計算ロジックの共通化、Google SpreadsheetとのCSV連携、Excel出力の一元化
- **機能要件**:
    - **マスタ検索**: ファイルNo.、会社名、ふりがなによる「あいまい検索」
    - **見積機能**: REAL4を含む各システムの台数に応じた段階価格の自動計算、消費税・合計金額の算出
    - **保守調整計算機**: 契約の重複（充当額）や空白期間、REAL4同期ルール（最大3ヶ月無料）の自動判定と計算
- **非機能要件**: セキュリティ（Google OAuth認証）、操作性（計算結果のダイレクト反映）、データの永続性（LocalStorageでの設定保存）

### 2. 仕様書 (Software Specification)
システムの具体的な実装方法、データ構造、計算ロジック、および UI/UX 仕様を技術視点で定義します。

**主な記載項目:**
- **技術スタック**:
    - **Frontend/Backend**: Next.js 14 (App Router), TypeScript
    - **Authentication**: NextAuth.js (Google Provider)
    - **Library**: `xlsx` (ExcelJS), `papaparse` (CSV解析)
- **システムアーキテクチャ**: App Router 構造、APIルートによる顧客データフェッチ
- **主要な計算仕様**:
    - **REAL4 計算ロジック**: 1台〜5台以上の段階単価の設定。
    - **日割り計算仕様**: 重複月数算出方法、月次単価ベースの日割り端数調整。
    - **REAL4 同期規定**: 特定期間（3ヶ月以内）における金額ゼロ化と備考欄への自動追記。
- **データ連携仕様**: Google Spreadsheet からの CSV エクスポート・取得（キャッシュ制限回避の設定含む）。
- **デプロイ・起動フロー**: 起動バッチファイルの内容、Next.js 開発サーバーの立ち上げ。

## ユーザーレビュー依頼事項

- 作成場所は、ユーザー様のご要望通り、プロジェクト内の `docs/project_documents/` フォルダ内とします。
- **追加の記載事項**: 特に重要なビジネスルール、あるいは今後の拡張予定（例：データベース化の予定など）があれば含めることが可能です。
- **フォーマット**: 基本的に Markdown 形式で作成しますが、PDFでの配布も考慮した構造（見出しレベル等）でよろしいでしょうか。
